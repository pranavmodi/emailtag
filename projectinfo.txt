Agentic AI Routing and Response Automation in FrontIntroduction: Understanding Agentic AI
Agentic AI refers to an AI system that can autonomously analyze, decide, and take action based on predefined rules and learned patterns. Unlike basic automation, which follows strict, static instructions, agentic AI adapts by understanding context, prioritizing tasks, and making decisions to improve efficiency.
In this case, our AI in Front is an agentic system that processes emails, live chats, and text messages, determines the correct department, applies relevant tags, and, when possible, automatically responds using templates or generated messages. If a message is too complex, the AI flags it for human intervention, ensuring seamless, intelligent automation across departments.

Goal

Improve Workflow Efficiency – By reducing manual sorting, tagging and replying, we enhance response times and improve task prioritization across teams.

Overview

The AI system in Front is being trained to analyze and process inbound emails, live chat messages, and text messages (SMS) using their subject, body, and OCR-processed attachments. This automation ensures efficient classification, routing, and response handling for different departments.



Objectives

1. Automate Message Routing – The AI will categorize and route inbound messages (email, live chat, and SMS) to the appropriate department based on content and attachments.
2. Apply Relevant Tags – AI will apply all relevant tags to further classify messages.
3. Automate Responses When Possible – Based on the department and tag, the AI will:

    * Use a predefined template to respond when applicable.
    * Assign a Human Review tag for complex cases requiring manual intervention.
    * BEFORE IT CAN REPLY it must be able to verify the sender of the email is able to receive the email by email address, domain, fax, etc and see if that is a player attached to any of the studies for the patient. If not simply tag for the request and add human tag review and cannot confirm player tag

  4.  Automate archival of unnecessary emails  - AI will determine if no reply is necessary and archive the message

    * Many messages do not reply a reply or being looked at.  Examples could be a reply saying thank you or I will keep my eye out for it, appreciate it, much appreciated,  Thanks a lot, thanks so much, etc
    * SPAM
    * Apply tag called "No Action Needed" then perform action " Archive"

📌 General Workflow & AI Processing Tags

These tags improve how messages are handled and tracked within the system.

* AI: Low Confidence (Used when the AI is unsure of classification and needs human input)
* AI: Cannot confirm player (Used when the AI cannot confirm if the user is allowed to get the documents)
* AI: Auto-Responded (Indicates the AI sent an automated response)
* AI: Awaiting Response (AI is waiting for a reply before taking further action)
* AI: Human Review Required (For unusual or urgent cases)
* Duplicate Request (Used when the same request was received multiple times)
* Follow-Up Required (For messages that need follow-ups before resolution)
* VIP / High Priority (For priority clients, attorneys, or doctors)
* Spam / Junk (For filtering out non-relevant or spam messages)

Suggested Workflow with an LLM



🚀 Summary of the Workflow

1. Front Webhook triggers when a message arrives and sends to local docker for preprocessing
2. Backend receives data, strips signature and footers extracts text, and runs AI classification.
3. AI determines the correct tag and action (route, respond, or escalate).
4. If AI response is possible, backend sends reply via Front’s API.
5. If human review is needed, AI adds a Human Review Required tag instead.

Since real-time processing isn't a factor, we will  focus on high-accuracy extraction and  cost savings :

1️⃣ Preprocessing: Email Cleaning & Signature Stripping

* Check comments if we have previously found the Patient ID.  If reply is related to new patient, run all the checks again
* Use heuristic-based signature detection:
    * Remove footers and disclaimers (often found in legal and corporate emails)
    * Remove previous replies that have already been analyzed and reviewed and previously tagged
    * Open-source tools EmailReplyParser, alternative, alternative2can help clean up raw emails.
* Check if there is an existing Patient ID in the email
    * Use regex to check for PRE then follow up numbers such as PRE100345 or PRE98733

2️⃣ LLM Processing for Classification & Entity Extraction

* Prompting Strategy:
    * Ask the LLM to classify the email into a department & subcategory based on its content.
    * Instruct the model to extract structured data (e.g., full names, phone # dates of birth, case details) while ignoring signatures.
    * Ensure it returns structured JSON for easy processing.

📌 Example Prompt for LLM:

markdown

Extract the following from the email: 1. Department: (Scheduling, Medical Records, Billing, etc.)2. Subcategory: (Appointment Status Request, Payment Issue, etc.)3. Full Name(s) and Date(s) of Birth (DOB)4. Find patient phone number Ignore email signatures and legal disclaimers.5. Return the output in JSON format.

✅ Example LLM Response:

json
CopyEdit
{
"department": "Scheduling",
"subcategory": "Appointment Status Request",
"name": "John Doe",
"dob": "02/15/1987"
"PatientPhone": "8185551212"
}


3️⃣ Postprocessing & Tagging

* Use a Named Entity Recognition (NER) model (like spaCy, Hugging Face BERT-based models) to validate extracted phone, names & DOBs.
    * We can find patient ID by finding the Patient ID, phone #, full name+DOB, full name+DOI
* Assign appropriate tags in Front based on the extracted department & subcategory.
* Insert Patient ID into comments if found.  If not found enter comment,  Patient ID not found
