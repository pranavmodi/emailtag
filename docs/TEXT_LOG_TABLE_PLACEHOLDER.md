# Text Log Table Placeholder

## Overview

The `{text_log_table}` placeholder is available in ALL autorespond templates. It generates a formatted HTML table showing the patient's text message history, including date/time and message type.

## Placeholder

```
{text_log_table}
```

**Type**: Common placeholder (available to all autorespond types)

**Description**: HTML table of patient text message history

## Usage in Templates

### Example Template

```html
<p>Dear {patient_name},</p>

<p>Thank you for your inquiry regarding patient {patient_id}.</p>

<p>Here is your recent text message history:</p>

{text_log_table}

<p>If you have any questions, please contact us.</p>

<p>Best regards,<br>
Precise Imaging</p>
```

### Rendered Output

The placeholder will be replaced with an HTML table like:

```html
<table border="1" cellpadding="8" cellspacing="0" style="border-collapse: collapse; width: 100%;">
    <thead>
        <tr style="background-color: #f2f2f2;">
            <th>Date/Time</th>
            <th>Message Type</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <td>01/23/2022 07:50 AM</td>
            <td>Appointment Reminder</td>
        </tr>
        <tr>
            <td>01/21/2022 11:18 AM</td>
            <td>Automated Message</td>
        </tr>
    </tbody>
</table>
```

## Data Source

The text log table is generated by:

1. **Fetching text history** via RadFlow API `textlog` endpoint
2. **Based on patient ID** extracted from the email/conversation

### API Details

See [RADFLOW_API.md](./RADFLOW_API.md) for full API documentation.

**Endpoint:**
```
POST https://staging-app.radflow360.com/chatbotapi/Patient/textlog?patientId={patientId}
```

**Headers:**
- `Authorization: Basic <credentials>` (from `RADFLOW_CONTACT_VERIFY_AUTH` env var)
- `Content-Length: 0`

**Response:**
```json
{
  "result": [
    {"patientId": "PRE701453", "dateSent": "2022-01-23T07:50:54", "textType": "PatSchedRemind"},
    {"patientId": "PRE701453", "dateSent": "2022-01-21T11:18:20.28", "textType": "Automation"}
  ],
  "status": 1,
  "responseStatus": "Success"
}
```

### Text Log Fields

Each text record includes:

- **dateSent**: Timestamp of the text message (formatted as MM/DD/YYYY HH:MM AM/PM)
- **textType**: Type of message sent, mapped to human-readable labels:
  - `PatSchedRemind` -> "Appointment Reminder"
  - `Automation` -> "Automated Message"
  - `Manual` -> "Manual Message"
  - `Confirmation` -> "Confirmation"
  - `Reminder` -> "Reminder"

## Implementation Details

### Backend

**File**: `app/helpers/text_log_table.py`

**Function**: `generate_text_log_table(patient_id: str) -> str`

**Process**:
1. Calls RadFlow textlog API with patient ID
2. Parses JSON response containing text history
3. Sorts by date descending (most recent first)
4. Formats data as HTML table with styling
5. Returns "no text activity" message if no texts found

### Frontend

**File**: `frontend/settings2/app/template-config/constants/placeholders.ts`

Added to `common` placeholders:

```typescript
{
  key: "{text_log_table}",
  description: "HTML table of patient text message history (Date/Time, Message Type)",
  example: "<table>...</table>"
}
```

### Agent Integration

The placeholder is automatically populated in:

1. **Lien Agent** (`app/agents/lien_agent.py`)
   - Generates text log when processing lien documents
   - Available in all lien templates (success, modified, invalid, etc.)

2. **Appointment Status Request Agent** (`app/agents/apt_status_req_agent.py`)
   - Generates text log when responding to appointment inquiries
   - Available in appointment status templates

## Table Styling

The generated table includes:

- **Header**: Gray background (#f2f2f2)
- **Borders**: 1px solid borders with collapse
- **Padding**: 8-10px for readability
- **Font**: Arial, sans-serif, 14px
- **Width**: 100% of container
- **Sorting**: Most recent messages first

## Edge Cases

### No Text History

If the patient has no text history, the placeholder will be replaced with a styled message:
```html
<p style="background-color: #ffeb3b; padding: 10px; border-radius: 5px;">
  <em>No text message activity found for patient as of {current_time}</em>
</p>
```

### Patient ID Not Found

If the patient ID is invalid or "N/A", the text log table will show the "no activity" message.

### API Failure

If the RadFlow textlog API fails or returns invalid data:
- Error is logged
- Placeholder is replaced with "no activity" message
- Email still sends (text log is optional data)

## Configuration

### Environment Variables

Uses existing RadFlow authentication:
- `RADFLOW_CONTACT_VERIFY_AUTH` - Basic auth header value

No additional configuration needed.

Show text history when responding to appointment inquiries so the patient/attorney knows when they were last contacted via text.

```html
<p>Here is your appointment information:</p>

{appointment_table}

<p>Recent call history:</p>
{call_log_table}

<p>Recent text messages:</p>
{text_log_table}
```

### 2. Lien Processing Confirmation

Include text history in lien confirmation emails to provide full communication context.

```html
<p>We have successfully uploaded your lien documents:</p>

{lien_status_table}

<p>Communication history:</p>
{call_log_table}

<p>Text message history:</p>
{text_log_table}
```
